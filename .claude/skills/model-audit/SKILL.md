# model-audit — 모델 독립 검산

엑셀 모델은 틀려도 아무 경고를 내지 않는다. 숫자가 나오면 그럴듯해 보인다.
검증 방법은 하나다. **같은 가정으로 다른 방법으로 계산해서 같은 답이 나오는지 본다.**

## 트리거
- 모델 최초 완성
- 가정·구조 수정 후
- IM에 결과를 옮기기 직전

## 절차
1. **독립 재계산** — 가정표만 입력으로 받아 같은 현금흐름을 다른 도구(예: `samples/*/model_check.py`)로 계산한다. 엑셀 수식을 베끼지 말고 가정표에서 새로 짠다. 그래야 같은 실수를 반복하지 않는다.
2. **대조표**
   | 지표 | 엑셀 | 재계산 | 차이 |
   - Project IRR, Equity IRR, 최저 DSCR(연차), 평균 DSCR, 1년 차 매출·비용·원리금
   - 소수점 첫째 자리까지 다르면 원인을 찾을 때까지 IM으로 넘기지 않는다.
3. **흔한 오류 점검**
   - **하드코딩**: 수식 칸에 숫자를 직접 친 곳. 모든 입력은 가정 시트 한 곳에서만 온다.
   - **타이밍**: 성능저하·물가상승을 1년 차부터 적용했나 2년 차부터인가. 이자를 기초 잔액에 매겼나.
   - **부호**: PMT·IRR 함수의 부호, 세금이 음수가 되는 해(MAX(0, …)).
   - **상환 구조**: 원금균등과 원리금균등 중 무엇을 썼나. 그 선택의 출처는 무엇인가.
   - **세금 기준**: Project IRR의 세금은 이자를 빼지 않고 계산했나.
   - **순환참조**: 건설기간 이자·DSRA가 대출액에 들어가며 생기는 순환을 의도적으로 처리했나.
4. **극단값 테스트** — 이용률 0, 금리 0, 대출 0을 넣어 결과가 상식대로 움직이는지 본다 (대출 0이면 Equity IRR = Project IRR).

## PASS/FAIL
- **PASS** = 대조표 전 지표 소수점 첫째 자리 일치 + 점검 항목 전부 확인 + 극단값 테스트 통과
- **FAIL** = 재계산 없이 엑셀 결과만으로 IM 작성, 원인 모를 차이 방치

## 이 스킬이 막는 실사고 (samples/solar-1mw)
- **상환 구조 가정**: 모델이 원리금균등을 썼다. 실제 은행 상품은 원금균등만 허용했다. 구조 하나 차이로 Equity IRR 16.1% vs 18.3%, 최저 DSCR 위치 1년 차 vs 15년 차가 갈린다. → 절차 3 '상환 구조'
