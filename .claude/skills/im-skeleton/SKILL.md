# im-skeleton — IM 골격

이 스킬은 빈칸을 만든다. 채우는 것은 작성자와 게이트다.
AI가 그럴듯한 숫자로 IM을 완성하면, 작성자는 그 숫자를 설명할 수 없다.

## 트리거
- 새 IM·사업성 검토 문서 시작

## 절차
1. `samples/<프로젝트>/` 폴더를 만들고 아래 파일을 둔다.
   - `IM.md` — 아래 장 구조
   - `assumptions.md` — assumption-trace 가정표
   - `gate-log.md` — 게이트별 실행일·판정·발견 사항
   - `model_check.py` — model-audit용 독립 재계산 (엑셀은 작성자가 직접 만든다)
2. `IM.md` 장 구조와 장별 게이트:
   | 장 | 내용 | 통과해야 할 게이트 |
   |---|---|---|
   | 0. 요약 | 투자 논리 3줄, 핵심 지표, 🔴 리스크, 가장 큰 변수 3개 | 전 게이트 통과 후 마지막에 작성 |
   | 1. 자산·시장 | 자산 개요, 산업 구조, 가격 결정 방식 | assumption-trace |
   | 2. 사업 구조 | 수익 출처, 계약 구조, 거래 참여자 | deal-thesis-gate |
   | 3. 공학 검토 | 성능을 결정하는 물리 변수와 그 불확실성 | assumption-trace |
   | 4. 재무 | 가정표, 기준 케이스, 민감도, 하방 시나리오 | stress-gate, model-audit |
   | 5. 리스크 | 배분표, 주인 없는 리스크 | risk-allocation-matrix |
   | 6. 회수(Exit) | 계약 종료 후 가치, 매각·재금융 경로 | assumption-trace |
   | 부록 | 출처 목록, 게이트 로그 | im-parity (발행 직전) |
3. 각 장에는 제목과 "이 장이 답할 질문" 한 줄만 쓴다. 숫자 칸은 `[ ]`로 비운다.
4. 요약(0장)은 마지막에 쓴다. 게이트를 통과하지 않은 장이 있으면 요약을 쓰지 않는다.

## 원칙
- 실제 비공개 자산의 IM을 흉내 내지 않는다. 공개 자료로 만든 가상 프로젝트, 또는 공개 정보만 쓴 분석으로 한정한다.
- 작성자가 면접에서 설명하지 못할 문장은 넣지 않는다.
